# 段位与称号判定规则（确定性口径）

> 本文件是 `scripts/mc_year_engine.py` 的**唯一口径来源**。改规则必须同时改这里与代码，
> 并跑 `python test/run_all.py` 回归——`test/run_all.py` 里有 20 余条针对数值的断言。

## 一、统计口径

| 项 | 规则 | 理由 |
|---|---|---|
| 纳入订单 | 只统计**未被取消**的订单 | 取消/退款的订单不代表真实消费行为 |
| 取消判定 | `orderStatus` 命中 `取消 / 退款 / 退单 / 关闭 / 已作废 / cancel / refund / closed` 之一即排除 | 覆盖中文状态文案与英文兜底 |
| 统计周期 | 默认 `--year`（缺省为 `now` 的年份）；该年无订单而历史非空时**自动回退为全部历史订单**，并在 `period.note` 如实标注 | 新用户/跨年用户不会被算成"零蛋" |
| 无时间订单 | `createTime` 解析失败的订单仍计入总单数与商品数，但**不参与**活跃天数与时段统计 | 不丢数据、也不虚构时间 |
| 数量取值 | 负数量 → 0；非数字/缺失数量 → 1；商品名为空 → 跳过该商品行 | 数据损坏时的最小假设，全部有测试覆盖 |
| 金额 | `realTotalAmount` 是字符串，剥离货币符号后取数值；缺失 → 0 | 实测存在 `"¥35.00"` / `null` / `""` 三种情况 |

**不做的事**：不推断缺失的门店/商品归属，不按金额给用户排名（避免消费攀比，
也符合活动规则关于"奢靡浪费、拜金主义"的内容合规要求）。

## 二、四项能力（每轴 0–25 分）

| 轴 | key | 公式 | 上限 |
|---|---|---|---|
| 菜单探索 | `explore` | `distinct_products × 1.5` | 25（≈17 种达标） |
| 麦门坚持 | `persist` | `active_days × 0.6 + active_months × 2.0` | 25 |
| 薅羊毛功力 | `value` | `coupon_count × 1.5 + usable_prizes × 3.0 + (used_point > 0 ? 2 : 0)` | 25 |
| 到店活跃 | `activity` | `order_count × 1.0 + time_bucket_variety × 1.5` | 25 |

* 每轴四舍五入到 1 位小数后 `min(25.0, …)`。
* `usable_prizes` = 奖品列表中 `statusText != "已失效"` 的条数。
* `coupon_count` 为 `None`（未知）时按 0 参与求和，但会在 `warnings` 中说明。
* 总分为四轴之和，范围 `[0, 100]`；`order_count == 0` 时强制全部归零。
* `time_bucket_variety` 只统计**已知时段的种类数**（0–5）。

### 时段划分

| key | 名称 | 区间 |
|---|---|---|
| `breakfast` | 早餐时段 | 05:00 – 10:29 |
| `lunch` | 午餐时段 | 10:30 – 13:59 |
| `teatime` | 下午茶时段 | 14:00 – 16:59 |
| `dinner` | 晚餐时段 | 17:00 – 20:59 |
| `midnight` | 夜宵时段 | 21:00 – 04:59（**跨零点**） |

`unknown` 不参与时段统计。并列时按 key 字典序取最小者，保证结果唯一。

## 五、为什么不交给语言模型算

| 维度 | 裸模型 | 本技能 |
|---|---|---|
| 数值 | 逐单"心算"，10 单以上开始出现偏差 | 脚本求和，105 条断言锁定 |
| 缺失字段 | 倾向于补一个"看起来合理"的值 | 显式留空并写入 `warnings` |
| 口径稳定性 | 同一份数据两次提问可能给出不同段位 | 同输入同输出，可回归测试 |
| 卡片版式 | 每次自由发挥，无法复现 | 纯函数渲染，字节级一致 |
